# 接入状态、验证证据与限制

核查日期：2026-10-18（北京时间）。应用 0.4.5，包名 `cn.onetap.checkin`。

用户在 0.3.0 交付后明确回复「测试完成，都可以正常签到」。这是**用户报告的原有四平台真机验收**，开发侧未取得凭证或独立操作设备；没有逐角色、跨日、后台和经验到账的完整证据。贴吧点赞与夜间模式不能继承这份验收。

0.4.5 按用户要求，贴吧普通签到提交后增加独立自检：以同账号网页身份和同吧 `forum_id` 的今日 `is_sign=1` 为完成依据，最多复查3次；提交成功码或重复码都不能单独完成。自检仍未签、缺项、异常均保留待确认；账号过期、验证码或身份改变立即停止。本地旧成功记录不能替代本轮自检，连续重试自检失败也不为此重复发送已完成记录的签到。

随机点赞确认赞已生效后即结束，不再另查经验或显示“经验待官方确认”。用户于2026-10-18提供的截图显示一个吧的本地点赞任务完成记录；未提供官方流水，开发侧也没有执行真实点赞。本次只移除额外经验提示，不修改点赞成功判定、不宣称具体经验数值；B站等级加速包仍显示独立经验状态。

0.4.4 按用户要求移除小黑盒。升级应删除旧小黑盒账号、凭证、历史与操作进度，并保留网易云音乐、百度贴吧、森空岛、哔哩哔哩的数据与设置。添加账号、首页、登录入口和任务执行均不再提供小黑盒。移除后的升级行为与数据隔离需分别以离线测试和本人手机覆盖安装确认。

贴吧 0.4.1 修正用户反馈的 `error_code=300000`，0.4.2 针对个别吧的帖子 / 贴吧身份不一致增加选帖前校验和零写入旧候选的一次恢复，并增加“取消全部随机一赞”。按钮只关闭本账号点赞任务，不撤销赞、不改变签到选择与历史。匿名读取受影响吧的 10 个公开帖子均未复现身份差异，不能宣称找到了唯一真实原因。

0.4.3 继续排查用户截图中的贴吧详情读取 error_code=4：公开控制帖在相同官方接口返回该码及“贴子可能已被删除”，但用户截图未包含具体帖子 ID 与服务端提示，不能证明其唯一原因。只对已核查的码/固定提示配对，在尚未发送写操作时继续检查同吧候选，每次最多10篇，找到有效对象才按原点赞次数上限执行；仅代码4或未知原因仍停止，发送操作后的上下文不换帖。诊断增加接口、公开帖ID与固定分类，不保留原始响应或账号标识。

0.4.4 同时处理用户反馈的贴吧主 forum_id=0：不在该帖写入，仅在零写入阶段跳过候选并继续原有同吧10篇限额；已发送操作不换帖。公开匿名9篇核查未复现该用户响应，具体原因仍未确认。详见 evidence/tieba-zero-forum-0.4.4.md。

## 最短新增功能验收

1. 使用同签名 0.4.5 覆盖安装，无需卸载。确认其他四个平台账号、勾选、历史与设置保留；小黑盒保持已移除。
2. 设置 → 外观切换深色 / 浅色 / 跟随系统，重开 App 确认保存，打开登录页检查原生工具栏可见。
3. 贴吧旧账号先「校验 / 刷新」，勾选各吧随机点赞任务，或点「全选随机一赞」。先启用一个吧执行，按结果中的吧名和帖子 ID 到官方核对；同日再执行不应取消重赞。再启用第二个吧，验证各自一天一帖。点「取消全部随机一赞」后，本账号全部点赞项应关闭，签到勾选和历史保持。旧失败项可点「仅重试失败 / 待确认项」；尚未发送操作且遇到已核实不可用候选时，最多检查同吧 10 篇，发送操作后的记录不能换帖。
4. 启用一个贴吧普通签到，执行后应先完成自检，再显示“自检通过，今日已签到”；到官方吧首页核对。当天再执行应只读确认已签。断网、自检缺项或仍未签时不能输出已签到；可稍后点“仅重试失败 / 待确认项”。原有成功记录遇本次自检不可用时应保留待确认，不冒充已签。
5. 检查首页、记录页和旧贴吧账号说明不再显示“经验待官方确认”；B站独立经验状态仍可见。遇登录失效或手动验证，先在官方登录更新授权，不发送凭证到聊天。

精确业务重置时刻仍需官方证据及跨日确认。本地暂按 UTC+8 零点分日，平台实时查询优先；贴吧点赞是工具的每日限额，完成checkpoint防止本地重复操作，不冒充官方经验任务。
