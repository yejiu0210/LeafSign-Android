# 更新记录

按版本从新到旧排列。0.3.0～0.4.5 的说明原文迁自旧版 README；对应 APK 见 [Releases](https://github.com/yejiu0210/one-tap-checkin-android/releases)，验证证据见 [verification.md](verification.md)。

## 0.5.10（2026-11-22）提示改成人话，渐变进度条

- **提示文字全部重写**：去掉「当前本地周期内已确认完成；平台无可靠只读查询，未重复发送」这类说明实现细节的长句，统一成「今日已签到」「签到成功」「结果未确认，请稍后重试」「账号已变化，请在账号页刷新」这样的短句。旧记录里的长句在界面上也会换成短句显示。
- B 站不再重复显示「经验：平台显示已领取」；等级加速包的结果直接写「今日已领取」「领取成功」「已领取，经验稍后到账」。
- **进度条**：改成一整根、不留缝的圆角条，填充从蓝渐变到紫，打开时从 0 涨到当前进度。
- **网易云成长值**：升级门槛的识别方式更多了（直接给门槛、给「还差多少」、等级列表三种）；仍然识别不了时，记录的诊断里会列出返回的字段名（不含任何值）。

## 0.5.9（2026-11-22）显示等级进度和签到所得，精简贴吧首页

- **贴吧首页精简**：首页只显示每个账号的「签到 x / y」「点赞 x / y」和需要处理的项，点「查看各吧详情」进入二级页面，按吧查看等级、经验进度和签到 / 点赞状态。
- **等级进度与数量**：签到后顺便读取各平台的成长数据，有升级进度的显示进度条和「当前 / 所需 · 百分比」：
  - 贴吧：每个吧的等级、经验进度、连签天数；签到成功时显示本次获得的经验。
  - 哔哩哔哩：账号等级与经验进度；大积分余额。
  - 网易云：黑胶等级与成长值进度；云贝余额（这两个接口的字段尚未用真实账号核对，对不上时记录里会写明未识别的字段名，不含任何值）。
  - 森空岛：明日方舟、终末地的今日签到奖励。
- 状态说明和右侧状态标签相同时（如都是「今日已签到」）不再重复显示。
- 读取这些数据失败时不影响签到结果；除网易云每轮各多一次只读查询外，不增加额外请求。

## 0.5.7（2026-11-22）平台图标改用官方 App 图标

- 各处的平台徽章，会优先显示手机上已安装的官方 App 图标（网易云音乐、百度贴吧、森空岛、哔哩哔哩、小黑盒）；没装的平台仍显示原来的文字徽章。图标从系统读取，不随安装包分发。

## 0.5.6（2026-11-22）修复小黑盒扫码后拿不到凭据

- **小黑盒扫码登录**：0.5.5 扫码确认后报「未返回登录凭据」。原因是请求没带网页端签名（hkey）和客户端参数，服务端虽然返回确认，但不下发登录 Cookie。现在扫码、轮询和身份校验都带上签名和整套网页端参数，并收集确认响应里的全部 Cookie。
- 仍然取不到凭据时，提示里会附上返回的字段名和 Cookie 名（不含任何值），方便排查。
- 修复检测不到小黑盒 App 的问题（Android 11 起需要在清单里声明要检测的包名），现在可以直接跳转小黑盒确认登录。

## 0.5.5（2026-11-22）小黑盒回归，改用扫码登录

- **小黑盒每日签到**：重新加入。登录改为用小黑盒 App 扫码（也可以手动导入 heybox_id 和 pkey Cookie），不再提供在手机上一直不稳定的网页登录。签到前先查任务中心，签到后再复查。
- **修复 0.4.x「登录后授权未生效 / 已过期」**：小黑盒每次校验身份都可能换发新的 pkey，旧版一次签到会校验好几次，而且在两个地方各自回写凭证，最新的 pkey 可能没存下来，下次就用失效的旧值。现在每轮只校验一次，新 pkey 由统一的流程保存，后续请求都用新值。
- 取消 0.4.4 加入的「启动时清理小黑盒数据」逻辑，新添加的小黑盒账号会正常保留。

## 0.5.4（2026-11-18）定时签到失败后自动重试

- **失败后自动重试**（设置 → 每日自动签到，默认开启）：定时签到结束后，如果有失败、待确认或中断的项，5 分钟后只重跑这些项；按北京时间每天最多 3 次，进程被杀或重启后会恢复待触发的重试。需要人工验证或登录失效的项不重试。主要解决零点高峰贴吧大面积 302 的问题。
- 重试使用独立闹钟，不影响每日定时闹钟、每小时备份任务和 Shizuku 守护；关闭自动签到或这个开关，会取消已排的重试。设置页的运行记录里显示为「失败重试」。

## 0.5.3（2026-11-18）改名一叶签，修复定时签到失败与待确认

- **贴吧 HTTP 302**：跳转不再一律报「服务器响应异常」。跳到百度安全验证的记为需要验证，跳到登录页的记为登录失效；临时跳转、5xx 和网络错误时，只读请求会等待后最多重试两次。签到请求结果不明时，先回读状态，确认仍未签到才补发一次。网页状态接口的跳转只影响自检，不再阻止 App 接口签到。诊断里会记下接口名和跳转目标主机，方便排查。
- **网易云**：黑胶乐签和云贝签到后，分多次回读服务端状态（约 5 秒），不再因为状态同步慢而显示「服务端尚未确认」。
- **文案精简**：结果提示改成简短说法（如「签到成功」「今日已签到」「结果未确认，请稍后重试」）。账号卡片只显示「上次校验时间 · 关注 N 个吧」这类一句话说明，删去说明性小字；修正设置页里过时的「1.5 秒」间隔说明。
- **改名**：应用由「一键签到」改名为「一叶签」（LeafSign）。桌面图标名称、首页标题、结果通知标题同步更新；扫码登录的二维码改存到相册 `Pictures/一叶签`（旧版本存下的图片仍留在 `Pictures/一键签到`）。包名 `cn.onetap.checkin` 与签名不变，可直接覆盖升级，本地数据不受影响。首页的「一键签到」按钮是操作名称，保持不变。

## 0.5.2（2026-11-13）新增云贝 / 大积分签到，修复提速引起的回归

- **新增**：网易云「云贝签到」（任何账号可用）；B 站大会员「大积分签到」（非大会员显示“需大会员”且不启用）。两者都先查询、后签到、再自检。老账号升级后自动出现并默认启用，无需手动刷新。
- **贴吧**：写请求间隔恢复为每账号 5 秒（0.5.0 的 1.5 秒触发了百度验证）；同账号先签到后点赞；被连带停下的项记为“执行中断”并说明原因，可用「仅重试失败 / 待确认项」补签；点赞触发验证不再影响签到。
- **森空岛**：同账号多个角色改回顺序执行，并复用同一会话（0.5.0 并发授权会互相作废，导致“登录失效”误报）；仅在 401 时重新授权重试一次。
- **网易云扫码登录**：改用 PC 客户端接口，整个流程固定设备标识并携带 NMTID 会话；遇到未知状态会显示状态码，8821 给出行为验证提示。

## 0.5.1（2026-11-13）官方 App 扫码登录、后台通知精简

**扫码登录**：添加账号新增「用官方 App 扫码登录（推荐）」，取代不便在手机上操作的电脑网页登录（网页登录与手动导入保留为备用）。本工具生成官方网页登录二维码（B 站、网易云、森空岛、百度），点「打开 App 确认登录」会尝试直接在已安装的官方 App 中打开；无法直接打开时自动把二维码存入相册（Pictures/一键签到）并拉起 App，在「扫一扫 → 相册」中选图确认。森空岛可用森空岛 / 明日方舟 App，贴吧可用贴吧 / 百度 / 百度网盘 App。确认后取得的凭证与网页登录相同，仍经各平台适配器校验身份后保存；贴吧会尝试补取 STOKEN 以支持签到自检。系统双开的分身 App 在拉起时由系统选择原版或分身；新增成功后可直接「继续添加」下一个账号。同一平台 ID 仍不能重复添加。各平台扫码协议依据开源实现整理，尚待真机验证。

**后台通知**：自动签到每次只发一条结果通知；「跳过」（今天已执行、正在执行、暂无网络等）不再弹通知，只写入设置页的触发记录；成功结果遵守「签到结果通知」开关，失败或有待处理项每天最多提醒一次；无网时备份任务不再挂前台通知；重复拉起的服务立即静默退出；通知均不响铃不振动。

## 0.5.0（2026-11-13）并发签到、准点定时与界面重做

**签到提速**：不同账号并行执行（设置 → 签到速度，1～8，默认 4）；森空岛同账号多角色最多 3 个并行、网易云 2 个，贴吧和 B 站同账号仍按顺序。贴吧写请求改为按账号分别间隔 1.5 秒（原为全部账号共用 5 秒），只读的身份、关注列表和签到状态做短期缓存，签到后自检强制拉新，等待由 1 秒 / 1 秒缩短为 0.4 秒 / 0.8 秒。本地加密数据改为内存缓存、写盘成功后才更新；网络连接池全进程共享。结果判定、写请求不盲目重试、身份防串号等原有约束不变。

**定时签到重做**：WorkManager 24 小时周期任务在国产 ROM 上不准点、进程被杀后不触发，改为多层保障——精确闹钟（默认闹钟模式，休眠时也按时唤醒）→ 前台服务执行（等待网络最多 90 秒，常驻通知显示进度，结束保留结果通知）；开机、应用更新、修改时间后自动重排并补跑当天；每小时一次的备份任务在错过时补跑；多个触发同时到达时按“当天已执行”原子去重，最多跑一次。设置页新增准点运行检查（精确闹钟、电池优化、通知、厂商自启动）、“1 分钟后测试一次”和最近 20 次触发日志。

**Shizuku 增强（可选）**：一键保活（电池优化白名单、允许后台运行、精确闹钟、待机分组设为活跃、通知权限、MIUI 自启动）；“Shizuku 守护唤醒”在 Shizuku 进程中常驻一个定时器，应用被系统杀掉或强行停止后到点仍会拉起签到。为此闹钟接收器和签到服务改为导出组件：外部调用没有应用私有随机 token 时一律按普通自动签到处理，仍受“自动签到开关 + 当天去重”约束，不能触发测试运行或重复写请求。手机重启后需在 Shizuku 中重新启动服务（已 Root 的设备会自动启动）。

**界面**：全新配色与渐变主卡片、今日完成率环形进度、实时显示并发进度；平台徽标与彩色状态标签；需关注的任务自动排前，长列表可折叠；账号页操作收进菜单；记录页按日期分组并可按状态筛选；设置页改为分区卡片，时间用时间选择器。启动图标改为自适应图标。

## 0.4.5（2026-10-18）贴吧签到自检

0.4.5 增加贴吧普通签到自检。提交返回成功码或重复签到码都不足以单独完成任务；只有身份匹配的服务端状态明确显示该吧今日已签才输出完成。自检不可用时，不用本地旧成功记录代替。只读状态入口最多返回200个吧，缺失目标会保留待确认；需要有效的官方网页会话，必要时重新网页登录更新凭证。

同版简化点赞完成判定：确认点赞生效后即完成，不单独查询经验，不再显示「经验待官方确认」；旧记录中的同类提示也会隐藏。

## 0.4.4（2026-10-17）移除小黑盒

0.4.4 已按用户要求移除小黑盒功能。覆盖安装后，旧小黑盒账号、凭证、历史与操作进度会从本地加密状态中清理；其他四个平台的账号、任务、记录及外观设置保留。

同版处理贴吧主 `forum_id=0` 的候选：不在该帖写入，仅在零写入阶段跳过候选，详见 [evidence/tieba-zero-forum-0.4.4.md](evidence/tieba-zero-forum-0.4.4.md)。

## 0.4.3（2026-10-17）贴吧选帖修复

贴吧保留 0.4.3 的处理：遇到已核实的“贴子可能已被删除”等不可用详情响应，继续检查当前吧最多 10 个不同候选，找到有效帖子后执行并确认点赞；已发送操作后状态不明不换帖。只有尚未发送任何操作且明确遇到其他帖子 / 吧 ID 或已核实不可用响应的旧候选，允许一次同吧恢复。真实账号修复效果仍待本人复测。

## 0.4.2（2026-10-17）取消全部随机一赞

修复登录会话导入与有界的同吧候选恢复；新增「取消全部随机一赞」。

## 0.4.1（2026-10-17）贴吧点赞协议修复

贴吧对照原 Android 客户端修正点赞对象参数，处理0.4.0用户反馈的 `300000` 相关不兼容。旧任务如果已到请求次数上限，只有同账号、同吧、同日最近明确记录该错误且当前帖子状态可确认时，允许一次同帖协议修复；不清空进度或换帖。安装后可点「仅重试失败 / 待确认项」，再到官方核对点赞；修复效果仍待真实账号验收。
